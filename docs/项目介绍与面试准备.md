# 项目介绍与后续学习

项目使用 C++17 和 Qt 开发本地图片批处理工具，支持预览、缩放、格式转换及文字水印。核心工程问题是：在窗口可操作的前提下并行处理图片，限制任务积压，降低大图同时解码的资源风险，并保证失败或取消后仍能得到完整结果。

## 可学习、可展示的技术点

| 技术点 | 对应代码 | 需要能解释的问题 |
| --- | --- | --- |
| 有界线程池 | threadpool.h / .cpp | 为什么需要队列容量？条件变量为什么使用谓词？析构如何结束线程？ |
| 异步结果 | ThreadPool::submit | packaged_task 和 future 怎样传值、传递异常？ |
| RAII 资源管理 | resourcebudget.h / .cpp | 为什么用租约？移动赋值或异常时怎样避免额度泄漏？ |
| 后台任务与界面 | batchworker / mainwindow | 哪个线程能改控件？队列满为什么不会卡住窗口？ |
| 正确性和取消 | batchengine | 如何保证进度单调、结果有序？为什么当前图片不能立即中断？ |
| 文件安全 | processor | 两个线程保存同名文件会怎样？怎样确认原图未改变？ |
| 性能实验 | tools/benchmark.cpp | 如何排除结果不一致的“加速”？预算峰值和工作集有何不同？ |

## 三天学习顺序（每天约五小时）

1. 第一天：运行软件；画出文件到输出的流程；阅读 processor 和参数结构；亲自修改一项处理参数并编译验证。掌握引用、对象生命周期、基本容器及错误返回。
2. 第二天：阅读独立线程池及预算模块；先运行 runtime_tests，再解释互斥锁、条件变量、future、RAII；亲自改队列容量观察背压。理解取消状态与 join 的关系。
3. 第三天：串联 Qt 信号和后台引擎；复现小规模基准；练习说明一个已修复问题、一次测试设计和项目局限；独立完成一个小改动并写清验证方法。

15 小时可用于建立项目整体理解并练习基础追问，不能保证掌握所有并发细节。遇到不能解释的实现，应继续实验或缩小简历表述。项目开发使用了 AI 辅助；学习后应按自己实际理解、修改和验证的工作描述贡献。

## 简历内容草稿（完成学习和实际操作后再使用）

**C++ 图片批处理工具｜C++17、Qt Widgets、CMake**

- 实现批量缩放、格式转换、水印、后台预览和处理报告，采用临时文件及重名编号保护已有文件。
- 实现固定线程池、有界队列及 RAII 预算控制，结合原子取消标记和 Qt 信号完成后台任务协作。
- 使用功能测试、并发测试和可复现基准验证程序；本机 36 张固定合成图片的 3 次重复实验中，4 线程相对单线程的耗时中位数加速约 2.84 倍。

仅保留自己能讲清楚的条目。性能数字必须同时说明测试环境和工作负载，不能写成所有场景的性能承诺。当前项目没有自定义内存分配器、无锁队列或分布式处理功能。
