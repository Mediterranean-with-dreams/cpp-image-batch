# 开发环境位置与维护

C++ 开发依赖位于项目根目录 `.tools`，运行程序包位于 `dist`。开发需要编译器和 SDK；普通使用只需完整解压程序包。

| 操作 | 入口 |
| --- | --- |
| 安装或补齐固定版本环境 | `scripts/Setup-Environment.ps1` |
| 编译 | `scripts/Build.ps1` |
| 测试及截图 | `scripts/Test.ps1` |
| 打包 | `scripts/Package.ps1` |
| 验证独立运行 | `scripts/Test-Package.ps1` |
| 启动软件 | `scripts/Run.ps1` |

脚本按项目路径调用工具，环境变量仅在当前进程临时使用并恢复，不写系统或用户 PATH。

## 中文路径兼容

MinGW 13.1 的部分工具使用中文安装路径时会出错。脚本自动在 `%TEMP%` 下创建 `imagebatch-dev-<项目路径哈希>` 目录联接，并临时设置 `GCC_EXEC_PREFIX`。联接只是英文路径入口，所有 SDK、源码及构建文件仍实际保存在项目里，没有复制另一套环境。

临时目录被清理后脚本会重建入口；不会覆盖指向其他位置的同名入口。

## 维护

1. 下载中断可重新运行安装脚本；若某个 SDK 损坏，先把对应目录改名备份再运行脚本补齐。
2. 完整重建：关闭程序，将 `.tools` 改名备份，重新运行安装脚本。
3. 移动项目后，将旧 `build-windows` 改名，再重新编译，避免 CMake 引用旧位置。
4. 升级时修改 `environment.json`，确保 Qt 与 MinGW 配套，并重新构建、测试。更改工具链目录名称时同步修改 `scripts/Common.ps1`。
5. 重新打包前，将原有分发目录和 ZIP 改名保留；打包脚本不会覆盖已有程序包。

首次准备需要联网。环境就绪后，构建、测试及运行可离线进行。Python 只用于准备工具，最终软件运行不需要 Python。
