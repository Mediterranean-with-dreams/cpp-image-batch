## 分发包验收

已将 v1.2.0 ZIP 解压到独立目录，清空 Qt/QML 开发路径，进程 PATH 仅保留 Windows 系统目录，启动包内实际 `ImageBatch.exe`，通过同一窗口完成三阶段验收：

1. 使用 2 个工作线程、64 MiB 估算预算，三张有效图片导出 JPG，损坏图片失败；横图缩为 80×50，竖图缩为 50×80，透明区转为白底，CSV / JSON 指标有效。
2. 点击“重试失败/取消”，只重试那张仍损坏的图片；报告仅记录该失败项，已有三张 JPG 保留且没有重复输出。
3. 仅勾选一张透明 PNG，选择“保持原格式”，导出一张透明 PNG，其他项不再处理，全部原图及损坏样本哈希未变。

[package-check.json](package-check.json) 的 `passed`、`all_originals_unchanged`、`parallel_batch_outputs_valid`、`batch_metrics_valid`、`retry_without_duplicates_valid`、`subset_original_format_valid` 均为 true，版本为 1.2.0。

该检查证明当前电脑上无需开发环境路径即可运行分发包，尚未在另一台全新电脑上验证。预览另外由 Qt 窗口自动测试覆盖，程序包诊断跳过异步预览，以便在临时样本目录清理前安全退出。

打包时 `windeployqt` 提示未找到 DXC/ DXIL；本项目使用 Qt Widgets 的二维界面，实际 Windows 平台启动和批处理验收通过。没有据此声称验证 Direct3D 渲染功能。

## 验证边界

本报告仅反映所列测试及当前电脑上的结果；没有覆盖所有图片编码变体、所有系统字体、长时间压力、内存耗尽、断电恢复、杀毒软件兼容、其他电脑及 Windows 其他版本。预算验证是估算额度不超限，不能解释为真实进程内存硬上限。AddressSanitizer / UndefinedBehaviorSanitizer 不等同于数据竞争检测，未运行 ThreadSanitizer。

## 性能与已修复问题

v1.2.0 已完成 6 张固定合成图片、1 / 2 / 4 线程的基准一致性检查。三次测量均成功导出、输入哈希未变、输出与预热完全相同；原始记录见 [本版一致性检查](benchmarks/v1.2-smoke/report.md)。这是一轮功能检查，不据此声称稳定加速比。下面的 36 图正式性能记录为 v1.1.0 历史结果。

2026-10-22，使用修复文件发布逻辑后的最终代码和固定 36 张混合合成图片，每种线程数测量 3 次：1 / 2 / 4 线程耗时中位数为 3793 / 2078 / 1336 ms，4 线程约为单线程的 2.84 倍速度。全部 9 次测量的输入哈希不变、输出哈希与预热相同，输出可重新读取且尺寸正确。每次采用独立进程，轮换执行顺序，预热不计入；文件缓存未清空。原始 JSON、CSV、语料清单和完整协议见 [性能记录](benchmarks/local-36-images/report.md)。

最初重复实验发现个别水印字形像素不稳定，因此没有接受那组性能结果。对文字绘制临界区串行化后，重新执行完整 9 次测量全部通过。解码、缩放、编码仍并行。该修复基于实际观测，未认定底层字体实现的根因。

初次 [Windows CI](https://github.com/Mediterranean-with-dreams/cpp-image-batch/actions/runs/39705168059) 暴露并发重名问题（16 个成功任务只有 13 个不同输出路径），本机重复运行亦复现。修复为关闭临时文件后使用不覆盖目标的原生文件发布接口；详见设计说明中的源码依据。修复后，同名输入及同名不同内容两组测试连续运行 20 次，共 1600 个图片输出，全部通过。此后重跑全量回归和性能实验，采用上述最新记录。
