## 分发包验收

已将 v1.1.0 ZIP 解压到独立目录，清空 Qt/QML 开发路径，进程 PATH 仅保留 Windows 系统目录，启动程序包内实际 `ImageBatch.exe` 的诊断入口。通过同一窗口，以 2 个工作线程、64 MiB 估算预算处理三张有效图片和一张损坏图片。

三张图片成功导出为 JPG，横图由 160×100 缩为 80×50，竖图由 100×160 缩为 50×80，透明背景转换为白底；损坏图片报告失败。CSV / JSON 计数与调度指标有效，全部原文件哈希不变。诊断记录 [package-check.json](package-check.json) 中 `passed`、`all_originals_unchanged`、`parallel_batch_outputs_valid`、`batch_metrics_valid` 均为 true，版本为 1.1.0，平台为 windows。

该检查证明当前电脑上无需开发环境路径即可运行分发包，尚未在另一台全新电脑上验证。预览另外由 Qt 窗口自动测试覆盖，程序包诊断跳过异步预览，以便在临时样本目录清理前安全退出。

打包时 `windeployqt` 提示未找到 DXC/ DXIL；本项目使用 Qt Widgets 的二维界面，实际 Windows 平台启动和批处理验收通过。没有据此声称验证 Direct3D 渲染功能。

## 验证边界

本报告仅反映所列测试及当前电脑上的结果；没有覆盖所有图片编码变体、所有系统字体、长时间压力、内存耗尽、断电恢复、杀毒软件兼容、其他电脑及 Windows 其他版本。预算验证是估算额度不超限，不能解释为真实进程内存硬上限。AddressSanitizer / UndefinedBehaviorSanitizer 不等同于数据竞争检测，未运行 ThreadSanitizer。

## 性能与已修复问题

2026-10-21，使用固定 36 张混合合成图片，每种线程数测量 3 次：1 / 2 / 4 线程耗时中位数为 5446 / 3274 / 2067 ms，4 线程约为单线程的 2.64 倍速度。全部 9 次测量的输入哈希不变、输出哈希与预热相同，输出可重新读取且尺寸正确。每次采用独立进程，轮换执行顺序，预热不计入；文件缓存未清空。原始 JSON、CSV、语料清单和完整协议见 [性能记录](benchmarks/local-36-images/report.md)。

最初重复实验发现个别水印字形像素不稳定，因此没有接受那组性能结果。对文字绘制临界区串行化后，重新执行完整 9 次测量全部通过。解码、缩放、编码仍并行。该修复基于实际观测，未认定底层字体实现的根因。
